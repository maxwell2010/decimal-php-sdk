# Bounded NFT position follow-up

The opt-in `tools/live_rpc_nft_position_search.php` searches exactly eight disjoint windows of at most 500 blocks per network, covering the latest 4000 blocks from each recorded snapshot. Requests use the strict read-only harness and a verified CA bundle. It reads at most six unique unheld positions. It does not scan all chain history or infer a hold timestamp absent from NFTDelegated.

The saved [raw artifact](live/nft-position-search.json) records 30 permitted RPC requests. Mainnet snapshot 0x20c2a6d has no matching events in that horizon. Testnet snapshot 0x1573aae has one event at block 0x1573910, transaction 0x9e01b143edf75ecebddc980c82943d47e32d6e7d7fa2c9067c9662613b02dac6.

That event identifies ERC721 0xe83e58cc6784b5263e4ddefd402b276b19720a84 ID 1, delegator 0x1dbcf18f1b9d36995e3db32965c276be92865b78 and validator 0x0fe8ea1b6b93f2113b6966c60604c658af56235f. The position is inactive at the latest snapshot, but active with amount 1 and nftType 2 at the event block. A withdrawal draft built by NftOperations for that exact delegator succeeds through eth_call at the event block, returning 0x. This establishes historical funded unified ERC721 withdrawal simulation, not a current funded exit or completed freeze/settlement lifecycle. No transaction was submitted.

An independent SDK input defect was also fixed: current ERC721 transfer previously discarded its amount argument and built a one-token transfer even for a requested amount 2. It now rejects noncanonical, zero and non-one ERC721 amounts before ownership RPC. Nonempty ERC721 data is rejected rather than discarded; use explicit transferFrom with safe=true for the bytes overload. This preserves the current Python three-argument transfer selector. Valid default transfers retain their existing calldata. Offline regressions check exact ERC721/1155 calldata, raw ERC721 bytes support, input boundaries before RPC and the recorded historical position/withdrawal at its pinned block.
