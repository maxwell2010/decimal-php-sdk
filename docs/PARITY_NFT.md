# NFT operation parity

NftOperations implements the Python NFT request semantics with raw decimal IDs/amounts, explicit reserve token/native total value, opt-in mintByETH profile clone, collection tuple5 versus DeployedNft tuple6, checked ownership and balance, approval planning and optional autoApprove. No mutation is broadcast. Parent TransactionPlan orchestration must confirm approval receipts and refresh state before preparing dependent action.

Every NFT catalog operation now has a named helper. Existing NftService transfer721/transfer1155 and DeployedNft remain available. NftOperations implements mint/burn/approval/batch/URI/reserve/create/disable plus stake delegate, hold, transfer and exits. Unified and legacy deployments are explicit; new legacy mainnet deposits fail before approvals. withdrawMany preserves duplicate IDs with distinct amounts and positional pairing. Unified exits use position-level NFT selectors with no invented amount argument.

NftStakingReader decodes the separate ten-field NFTStake into named fields and preserves pinned block. NftReader supplies Python/C# NFT queries with source-derived C# ABIs stored in resources/nft-erc*-csharp.json. Calling an ERC721-only query on ERC1155 fails rather than guessing a balance/owner equivalent.

Independent eth_abi5.2.0/eth_utils fixtures check exact calldata/value for reserve mint variants and sixteen legacy/unified held/unheld exit/transfer combinations. Negative tests check missing approval, mismatched arrays, accumulated duplicate-ID batch balances, reserve conflict, ownership failure and blocked legacy mainnet deposit. Additional state-role enforcement remains node-authoritative and can be checked with Client::simulate; drafts do not assert role membership.

The broader C# NFT inventory is additionally covered by createReservelessCollection/addReserve/addEthReserve, NftReader and NftReceipts::created/movements/uriUpdates. Ordered receipt movement arrays preserve duplicate NFT IDs and reject batch pairing mismatches. ABI profiles remain explicit because reserve-native ETH and DEL selectors are deployment-specific. See parity-nft.json for source hashes and helper mapping.

NftPermitService implements the distinct reviewed DRC721 and DRC1155 EIP-712 permits. Owner is the recovery identity, not a signed field. DRC721 signs spender/tokenId/nonce/deadline and reads token-ID nonces/current ownership; DRC1155 signs spender/nonce/deadline and reads owner nonces, granting operator-wide approval. Explicit version must match the actual on-chain DOMAIN_SEPARATOR. prepare checks current chain/name/domain/nonce and deadline; verifyExternal refreshes those checks before EOA recovery. sign uses deterministic wallet signing and rejects deployed contract owners for721. draft is explicitly an unsigned ABI-only envelope, with no implicit state assurance. Independent eth_abi/Keccak vectors and stale-nonce/domain/owner/deadline negatives cover these boundaries.

NFT permit raw/external signatures enforce nonzero in-range r and low-S s with EOA v27/28. External721 verification also rejects deployed contract owners rather than pretending EIP-1271 acceptance. Receipt sorting filters foreign emitters first and rejects removed matching movement/URI logs; malformed unrelated log indices do not poison matching collection reads.
